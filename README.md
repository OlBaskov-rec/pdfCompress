# PDF Compress — пакетное сжатие PDF

Приложение для Windows: указываете папку, выбираете степень сжатия **или** предельный размер
файла — и получаете сжатые копии всех PDF из папки. Внешние утилиты не нужны: ни Ghostscript,
ни qpdf, ни установленный .NET.

## Возможности

- **Папка → список PDF.** Показываются только PDF-файлы с размерами; при желании — из вложенных
  папок. Каждый файл можно исключить флажком.
- **Два взаимоисключающих способа задать сжатие** (активен ровно один, второй в это время
  выключен и приглушён — это видно в окне):
  - **степень сжатия** — бегунок на 5 положений, под ним подписано, что именно означает
    выбранное («150 dpi · JPEG 75 — для документооборота»);
  - **максимальный размер файла** — число и единица измерения (Б / КБ / МБ / ГБ, по умолчанию МБ).
    Параметры подбираются автоматически: программа ищет самое щадящее сжатие, при котором файл
    ещё укладывается в предел.
- **Результат по каждому файлу**: было → стало и процент экономии, плюс итог по всей пачке.
- **Ничего не теряется.** Исходные файлы не трогаются, результаты пишутся в отдельную папку
  (по умолчанию — подпапка `compressed`). Если сжать не удалось, туда всё равно кладётся копия
  оригинала, чтобы комплект документов был полным.
- **Обработку можно прервать** кнопкой «Отмена»; уже готовые файлы остаются на месте.
- **Авто-обновление** (Velopack, GitHub Releases).

## Как это работает

Основной вес «тяжёлых» PDF — растровые изображения, поэтому движок работает именно с ними.

1. **Считается реальное разрешение картинки на странице.** Разбираются потоки содержимого
   (операторы `q`/`Q`/`cm`/`Do`, включая вложенные Form XObject), и для каждого растра
   вычисляется его размер в пунктах. Без этого «целевое dpi» бессмысленно: снимок 2000×1500
   может занимать целую страницу A4 (≈170 dpi — трогать нечего) или клетку таблицы в сантиметр
   (≈5000 dpi — можно ужать в 30 раз).
2. **Лишние пиксели убираются.** Всё, что подробнее заданного dpi, уменьшается (увеличение
   исключено) и перекодируется в JPEG. Полутоновые оригиналы кодируются в **серый** JPEG —
   меньше байт и никакой цветной каймы по краям букв.
3. **Замена только при реальном выигрыше.** Новый поток ставится на место старого, лишь если он
   минимум на 10 % меньше исходного. Уже оптимизированные документы не портятся ради процента.
4. **Потоки перепаковываются** (Flate, максимальное сжатие) при сохранении документа.

Намеренно **не трогаются**: штриховые сканы (CCITT, **JBIG2**, 1 бит на пиксель), индексированные
палитры, картинки с нестандартной таблицей `/Decode` и цветовым маскированием, JPEG 2000. Все они
либо уже сжаты лучше, чем получилось бы у нас, либо от перевода в JPEG заметно испортились бы.
Маски прозрачности (`/SMask`) уменьшаются, но всегда **без потерь** — JPEG на альфа-канале даёт
ореолы по краям.

### Степени сжатия

| Степень | dpi | JPEG | Для чего |
|---------|-----|------|----------|
| 1 — Минимальное | 300 | 92 | почти без потери качества |
| 2 — Слабое | 220 | 85 | качество печати |
| 3 — Среднее | 150 | 75 | документооборот (по умолчанию) |
| 4 — Сильное | 110 | 60 | чтение с экрана |
| 5 — Максимальное | 72 | 40 | минимальный размер |

Режим предельного размера идёт по той же шкале, но непрерывно: сначала проверяется максимальное
сжатие (если и оно не укладывается в предел — дальше искать нечего), затем двоичным поиском
подбирается самый мягкий вариант, который ещё влезает. Всего до 5 проходов на файл.

### Чего ждать от сжатия

Выигрыш целиком зависит от того, что внутри документа:

| Документ | Было | Стало (Среднее) | Стало (Максимальное) |
|----------|------|-----------------|----------------------|
| Скан-справка, JPEG 300 dpi | 246 КБ | 112 КБ (−55 %) | 21 КБ (−91 %) |
| Выписка с картинками | 189 КБ | 137 КБ (−28 %) | 123 КБ (−35 %) |
| Скан 2 стр., уже сжат под 200 dpi | 554 КБ | без изменений | 124 КБ (−78 %) |
| Книга 516 стр., скан JBIG2 | 7,2 МБ | без изменений | без изменений |
| Текстово-векторный документ | 858 КБ | 847 КБ (−1 %) | 847 КБ (−1 %) |

Последние две строки — не недоработка, а правильный ответ: JBIG2-скан и векторный документ уже
сжаты лучше, чем дало бы пересжатие в JPEG.

## Архитектура

```
src/
  PdfCompress.Core/                  # Библиотека без интерфейса — кросс-платформенная, тестируемая
    Models/                          #   уровни, единицы размера, задание и результат
    Services/
      PdfFileScanner.cs              #   поиск PDF в папке
      ImagePlacementAnalyzer.cs      #   реальный размер растра на странице (разбор потоков)
      PdfRawImageDecoder.cs          #   сырые (не-JPEG) растры -> битмап
      PdfImageRecompressor.cs        #   уменьшение и перекодирование растров
      PdfCompressionService.cs       #   сжатие файла: по степени или под целевой размер
  PdfCompress.Desktop/               # Приложение Avalonia, ссылается на Core
    ViewModels/MainViewModel.cs
    Services/                        #   выбор папки, настройки, журнал, обновления
    MainWindow.axaml(.cs)
tests/
  PdfCompress.Core.Tests/            # xUnit-тесты движка
```

Ядро (`PdfCompress.Core`) не зависит от интерфейса — это упрощает тестирование и оставляет
открытой дорогу к консольной версии и к macOS/Linux (Avalonia и Skia кросс-платформенны).

## Требования

- **Windows 10** и новее. Манифест объявляет совместимость и с Windows 8.1 / 7, но проверялось
  только на Windows 10.
- Для запуска portable-сборки рантайм не нужен (self-contained).
- Для сборки из исходников — **.NET 10 SDK**
  ([скачать](https://dotnet.microsoft.com/download/dotnet/10.0)).

## Portable-сборка и обновления (Velopack)

Распространение — **portable self-contained** сборка с авто-обновлением через
[Velopack](https://velopack.io). Фид обновлений — GitHub Releases публичного репозитория
(токен для скачивания не нужен).

- `VelopackApp.Build().Run()` вызывается первым в [Program.cs](src/PdfCompress.Desktop/Program.cs)
  и обрабатывает хуки установки и обновления.
- В режиме разработки (`dotnet run`) проверка обновлений — безопасный no-op.

Инструмент `vpk` подключён через манифест `.config/dotnet-tools.json` (восстанавливается
автоматически).

```powershell
pwsh build/pack-win.ps1 -Version 0.1.0
```

```powershell
pwsh build/pack-win.ps1 -Version 0.1.0 -Upload
```

Для `-Upload` нужен GitHub PAT с правом **Contents: Read and write** на репозиторий `pdfCompress`
в переменной окружения `GITHUB_TOKEN` (в репозиторий его не коммитим).

Артефакты в `.\Releases`:

- `PdfCompress-win-Portable.zip` — portable-приложение (со встроенным `Update.exe`);
- `PdfCompress-win-Setup.exe` — установщик;
- `*-full.nupkg`, `RELEASES`, `releases.win.json` — пакет и метаданные фида обновлений.

> **Версионирование:** поднимайте `<Version>` в
> [PdfCompress.Desktop.csproj](src/PdfCompress.Desktop/PdfCompress.Desktop.csproj) (или передавайте
> `-Version`) перед каждым релизом — Velopack обновляет клиентов только на бо́льшую версию.

## Где приложение хранит свои данные

`%AppData%\PdfCompress\`:

- `settings.json` — папки и параметры последнего запуска;
- `window.json` — размер окна;
- `log.txt` — журнал (ошибки чтения PDF, сбои записи, падения).
